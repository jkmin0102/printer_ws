# 실행 검증 기록

## 2026-11-17 레이저 표시·화면 구성·Nav2 중단 보완

Gazebo의 실제 LDS-02 ray 시각화를 켰고, 실행한 gzclient 안에서만 좌측 메뉴를 접는 GUI 플러그인을 추가했다. 두 창은 녹화 여부와 관계없이 데스크톱 작업 영역을 채운다. RViz는 받은 지도 크기와 실제 viewport에 맞춰 지도를 확대하며 수동 조작 후 전체 맞춤 버튼을 제공한다. 영상의 두 번째 자막 줄은 삭제했다.

종료 원인 조사와 수정:

- 사용자 제공 로그는 `WORK_APPROACH`의 `status=6`만 포함하므로 해당 실행의 원인은 확정할 수 없다.
- 수정 전 `20261117_070157_approach_reproduce`는 접근·물리 집기 후 출발 중 `compute_path_to_pose` ACK 시간 초과로 중단됐다가 기존 G 재시도로 도착했다.
- 화면·녹화를 켠 `20261117_070518_laser_gui_reproduce`에서는 같은 ACK 시간 초과가 `APPROACH`에서 발생해 전체 실행이 실패했다. 상세 `navigation.log`와 원본 영상은 보존했다.
- 설치된 Humble `bt_action_server_impl.hpp:120`에서 `default_server_timeout`이 milliseconds임을 확인했다. 20 ms를 1000 ms로 수정했다. 센서·경로·팔 신선도 검사, 충돌 검사, 목표 위치 허용 오차는 유지했다.
- 작업 목표 후보에 실제 Nav2 경로 검증을 추가했다. 작업 접근 중 action abort는 정지, 새 scan 4회, costmap 갱신, 같은 작업 목표의 실제 경로 검증 후 최대 2회만 재시도한다. 경로 없음·센서 오류는 계속 실패로 처리한다. 작업 재시도에서 G 경로를 잘못 검사하지 않도록 테스트했다.
- Nav2 경고·오류를 결과와 RViz/터미널에 연결했다. `--no-save` 실패에서도 임시 로그를 삭제하기 전에 상세 오류를 출력한다. 새 진단 기능의 Humble Log 상수 bytes/int 호환 오류가 발생한 `20261117_070749_laser_navfix_A`도 보존했고, 실제 Log 메시지 회귀 테스트로 수정했다.

`20261117_070846_laser_navfix_A2`: GUI·녹화·원본 YOLO 전체 A 성공. coke 신뢰도 0.6782, 작업 위치 오차 6.56 mm, 캔 상승 8.29 cm, pinch/hold/release 확인, 반지름 전체가 녹색 적치 공간 안이다. 추정 위치 도착 오차 3.21 cm, world 기준 5.36 cm. 적치 후 G 목표 한 번과 경로 57회 갱신으로 완료했다. action abort와 재시도는 없었다. 순간 충돌 예측 경고에서 정지하는 동작은 유지되며, 항상 정지 없이 부드럽게 주행한다는 뜻은 아니다.

`20261117_071543_laser_navfix_B2`: GUI·녹화 B 우회 성공. 캔 XY 이동 1.64e-17 m, REMOVE 호출 없음, 추정 위치 도착 오차 7.73 mm/world 기준 4.11 cm. 선택 후 실측 64.0 sim s이며, 예측 48.81초와 구분한다. action abort 없음.

B의 첫 실행 `20261117_071240_laser_navfix_B`는 주행 전에 `/map_server/change_state` DDS 응답 유실로 준비 제한 시간에 걸렸다. 종료 때 별도 프로세스 그룹인 lifecycle manager가 남는 문제를 확인해 실행 자식의 PID+생성 시각 추적과 제한 시간 후 정리를 보완했다. 독립 그룹 자식의 부모 종료 이후 정리와 PID 재사용 방지 테스트를 추가했다. 이전 사용자 실행 `20261117_064552_A`의 프로세스도 기존 도메인 44에 남아 있음을 확인했으며, 다른 실행으로 구분하여 자동 종료하지 않았다. 기본 도메인 추가 실행은 자동 승인 검토에서 충돌 위험으로 거부되어 추가 검증은 독립 도메인 96/포트 11496을 사용한다. DDS 초기 응답 유실 자체가 모든 환경에서 해결됐다는 주장은 하지 않는다.

새 영상은 `presentation/laser_view/demo_ab.mp4`, 1848×1062, 157.5초다. 실제 A/B 원본 녹화를 보존하고 창 제목·도구 모음 등 위아래 가장자리만 잘랐다. A 접근/B 주행 3배속, 집기 1.25배속, 적치 후 G 이동 1배속을 한 줄 자막으로 표시한다. 전체 디코딩 검사와 A/B 프레임 시각 검사를 통과했다.

추가 `--no-save` A 실행은 작업 접근까지 완료한 뒤 안정 인식 부족으로 안전 정지했다. 임시 디렉터리 삭제, 새 실행 폴더 없음, 해당 실행의 자식 프로세스 0개를 확인했다. 전체 성공 실행으로 계산하지 않는다. 이후 `20261117_072320_camera_recheck`에 동일 인식 실패가 재현됐으며, 보존한 RGB를 원본 모델로 다시 추론한 coke 신뢰도는 0.4796으로 기준 0.5 미만이었다. 성공 영상의 비교 프레임은 0.7089였다. GUI 레이저는 실제 카메라 영상에 그려지지 않음을 확인했다.

인식 재관측 보완: 베이스를 정지하고 기본 인식 자세에서 12초 이내 새 안정 관측을 기다린다. 미확보 시 관측 자세의 joint1을 기본값 기준 -5°, +5°로 최대 두 번 실제 이동하며 각 자세에서 새 RGB-D 관측을 확인한다. PREPARED·빈 그리퍼·정지/신선도 인터록을 만족해야 하고 전체 관절 경로의 충돌 검사를 수행한다. 원본 best.pt, 신뢰도 0.5, 안정 관측 3회, 좌표/시각 검사와 SIM_RED 자동 전환 금지는 유지한다. 실패 원인과 재관측 횟수를 결과에 기록하고 카메라 상태를 RViz/터미널에 표시한다.

최종 `20261117_072805_bounded_views_A`는 원본 YOLO로 집기·적치·도착까지 성공했다. 기본 관측에서 인식돼 재관측 호출은 없었다. 캔 상승 8.23 cm, 전체 적치 공간 안, 추정 위치 오차 2.71 cm/world 오차 6.70 cm, G 목표 1회/경로 70회 갱신이다.

`arm_validation/20261117_laser_views`는 독립된 정지 베이스·빈 바닥 fixture 시험이다. 실제 관절로 77°→72°→82°를 수행했고 각 목표의 joint1 오차는 1.8e-6 rad 이하였다. 77°/72°에서 새 YOLO 안정 관측 신뢰도는 0.706/0.882였다. 82°에서는 인식 기준을 충족하지 못했으며 성공 관측으로 처리하지 않았다. 캔 변위 0, 세 번째 VIEW 요청 거부를 확인했다. 이 fixture는 벽 없는 세계라 static collision map을 요구하지 않았으며, 실제 미션의 정적 지도 충돌 검사는 계속 켜져 있다. 임의의 관측 자세가 항상 인식에 성공한다는 뜻은 아니다.

최종 A/B·인식 재현·추가 A의 ROS launch 자식 64개는 모두 종료됐다. 이전 사용자 실행의 프로세스는 구분하여 보존했다. 추가 실패와 재관측 시험을 포함한 요약은 `presentation/laser_view/verification.json`에 기록했다.

단위·회귀 테스트 92개 통과, 7개 패키지 빌드 성공. 원본 EATED 소스 53개와 best.pt SHA256은 변경되지 않았다. 기존 영상·실패 기록은 삭제하지 않는다.

## 인식 범위

앞서 제시한 A/B 녹화와 독립 물리 집기 검증은 명시적인 **SIM_RED** 모드다. 이후 원본 YOLO 통합 완주도 성공했으며 아래에 별도 기록했다. 실제 손목 RGB 영상과 등록 depth,
동일 시각 TF, 알려진 세워진 캔 크기를 사용한다. 생성 위치 또는 Gazebo 정답 좌표를
인식·행동 선택·팔 목표에 제공하지 않는다. 정답 좌표는 별도 읽기 전용 probe의
사후 평가에만 사용한다.

원본 `best.pt`는 변경 없이 연결되어 있으며 기본 모드는 strict YOLO다. 주행 작업
자세에서 얻은 실제 렌더링 영상을 재추론했을 때 `coke=0.184`로 기준 0.5 미만이었다.
증거는 `yolo_main_recognition_pose/evidence.json`에 있다. 이 오프라인 실패와 이후 통합 YOLO 성공은 서로 다른 시점의 입력이다. SIM_RED 성공을 YOLO 성공으로 해석하지 않는다. 학습 실물 사진과 Gazebo 렌더링 차이, 실제 hand-eye 보정은
남은 과제다. 자세한 내용은 [PERCEPTION.md](PERCEPTION.md)를 참고한다.

## 실패에서 수정한 사항

- TF 0.25.23 교착: 공식 0.25.24의 로컬 실행 라이브러리로 수정. 시스템 ROS 설치는 보존.
- 차체 기울어짐·바퀴 미끄러짐: 질량/무게중심 가정을 명시하고 유효한 접촉 마찰 방향 적용.
- 팔 PID 진동·토크 포화: 유한 힘 제어를 유지하며 D gain과 시뮬레이션 토크 한계 수정.
- 놓기 직후 손가락 접촉: 벌리기·정착·후퇴 이후 실제 분리를 확인하도록 순서 수정.
- 계산 중 안전 메시지 지연: 팔 센서 수신을 별도 callback group으로 분리. 안전 제한은 유지.
- 작업 위치 진입·출구에서 벽 접근: 통로 중앙 경유점을 실행 및 비용 계산에 함께 포함.
- 라벨에 따른 관측 중심 편향: 단일 픽셀 대신 실제 깊이 옆면 원호를 맞추고 크기·잔차·관측 범위를 검사.
- 재시작 시 초기 팔 접힘: 관절 한계에서 여유가 있는 초기 배치로 수정하고 실제 STOW 검증 유지.
- LiDAR/TF 도착 위상 차이: 새 스캔의 TF가 아직 없으면 큐의 직전 유효 스캔을 원래 시각으로 처리. 새 메시지가 직전 것을 계속 덮어쓰던 문제 수정.
- 짧은 TF 지연에 Nav2가 즉시 실패: 정지 명령 상태에서 회복하는 유한 대기를 2초로 설정.
  별도 주행 중재기의 센서·제어기 신선도 차단은 완화하지 않았다.

실패 기록도 실행 폴더에 남겼다. 한 번의 성공으로 반복 성공률을 보증하지 않는다.
